# data09-25 · 주조 생산실적 분석

주간 주조 생산실적 엑셀을 여러 주 쌓아 품목별 분석·주간 생산결산·이상 탐지(규칙 + AI 프롬프트)·주간 보고서 초안을 만드는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 정윤욱 |
| 과정 | 현장 데이터 수집·디지털화 전문가과정 1차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-09-29) — https://aebonlee.github.io/data09-25/ |
| 다음 개발 | 2단계 — 팀 공유 DB, 작업일지·불량 연계, 조치 기록, 표준 사이클타임 비교 |

> 과제는 메일로 접수했습니다. 첨부 주간표에는 작업자 실명·실제 품번이 있어 **이 리포에 넣지 않았습니다.** 샘플은 같은 모양의 가상 값입니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data09-25/**

처음 열면 「데이터 가져오기」 화면입니다. **「샘플 8주로 시작」** 을 누르면 가상 8주가 들어가고 ③ 이상 탐지 화면으로 넘어갑니다(7·8주차 4호기 비가동 증가, 8주차 SMP-P202 폐기율 급증을 일부러 심어 두었습니다).
실제로 쓸 때는 매주 쓰시는 「주조 생산현황」 엑셀을 여러 개 한꺼번에 넣으면 됩니다. 파일은 서버로 보내지 않고 이 브라우저 안에서만 읽고 저장합니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS).

| 화면 | 하는 일 |
|---|---|
| 데이터 가져오기 | 주간 엑셀 여러 개 · 2줄 머리행 자동 인식 · 열 연결 확인/수정 · 점검 알림 · 같은 행(일자+호기+품번+주조일자) 중복 제거 · 다음 주 계획 행 → 실적 행 대체 · 비가동 범례 자동 읽기 |
| ① 품목별 분석 | 품목·기준 주·4/8/12주 — 계획 대비 양품, 달성률, 양품률·폐기율, 시간당 양품, 추이 그래프 4개와 표, 호기별 생산성, 이번 주 작업 행 |
| ② 주간 생산결산 | 주 또는 날짜 범위 — 품명 → 품번별 계획시간·실투입시간·계획수량·양품·폐기·미달·달성률·폐기율·비가동 코드별·비가동내용, 엑셀 내려받기·인쇄 |
| ③ 이상 탐지 · AI | 직전 N주 중앙값 대비 시간당 생산량 저하·달성률 저하·폐기율 증가·비가동 증가(품목·호기), 근거 숫자와 비가동 상위 코드, 기준 바꾸기. 계산된 사실만 담은 AI 프롬프트(복사·붙여 넣기, 선택: 설정한 AI 서버로 자동 보내기) |
| ④ 주간 보고서 | 총괄·품명별·주요 문제·호기별·다음 주 계획·AI 의견 — 인쇄/PDF, Word, 엑셀, 글자 복사 |
| 설정 | 비가동 코드 이름·계획정지, AI 연결(OpenAI 호환 주소·모델·본인 키, 기억은 선택), JSON 백업 |

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음)
- 샘플 파일 다시 만들기: `node scripts/make-samples.js` → `samples/` 8개
- DB 스크립트 검증: `./scripts/sqltest/run.sh` (로컬 PostgreSQL 필요)

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| ① 품목별 생산분석 | 완료 | 호기 비교는 실제 주조호기 기준 |
| ② 주간 생산결산 | 완료 | 보내 주신 요약 시트와 같은 합계(로컬에서 21행 모두 일치 확인). 실제 결산표 양식이 다르면 맞춤(기획서 10장) |
| ③ AI 생산분석 | 완료(규칙 + 반자동 AI) | 규칙이 근거와 함께 찾고, AI 는 그 사실만으로 요약·확인사항. 조치 기록 기반 원인 추천은 2단계 |
| ④ 주간 보고서 | 완료 | 초안 — 검토 후 사용 |
| 팀 공유·동기화 | 2단계 | DB 스키마·검증 하네스는 준비됨 |
| 작업일지·불량 상세 | 2단계 | 양식 확인 후 |
